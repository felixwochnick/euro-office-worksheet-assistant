# 3D scenes of geometric bodies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `scene_3d` worksheet block: the AI describes geometric bodies, the assistant computes a colouring picture
(vector lines, hidden lines removed) and a coloured, shaded version (three.js/WebGL in the plugin).

**Architecture:** A new dependency-free shared module `packages/shared/worksheet-3d.js` normalises the scene, places the
bodies, sets up the camera and computes the line drawing analytically (all bodies are convex: exact silhouettes,
ray-interval visibility, intersection curves by marching squares on the surface patches). It returns an SVG plus a
render description. `worksheet-layout.js` turns it into an image run; in the plugin, `rasterize` renders the coloured
fill with a vendored three.js bundle (`apps/plugin/src/js/scene3d.js`) and puts the vector lines on top.

**Tech Stack:** plain ES2015 UMD modules (shared), node:test, TypeScript server (tools/prompt), three.js 0.187.0
bundled with esbuild for the plugin, Playwright for the browser check.

**Spec:** `docs/superpowers/specs/2026-11-23-3d-scenes-design.md`

## Global Constraints

- Shared modules: UMD (`module.exports` / global), dependency-free, ES2015, synchronous, deterministic.
- Graphic result convention of `worksheet-svg.js`: `{ svg, widthMm, heightMm }`, viewBox in mm, no background,
  lines ≥ 0.25 mm, text ≥ 3 mm.
- Block field names and defaults exactly as in the spec tables (`bodies`, `style`, `projection`, `view`, `elevation`,
  `hidden_edges`, `ground`, `color_by`, `width_cm`, `caption`; body `shape`, `size`, `radius`, `height`, `at`, `on`,
  `turn`, `lying`, `id`, `label`, `color`). Max 40 bodies.
- Shape colours: cube red, cuboid blue, sphere yellow, cylinder green, cone orange, pyramid purple, triangular_prism
  brown; named colours red, blue, yellow, green, orange, purple, brown, gray, white.
- Error messages English, actionable, naming the body index (`bodies[3]: …`).
- pnpm only; files and identifiers in English.
- Implementation decision (recorded in the spec): the line drawing needs no three.js; `isometric` honours
  `front_left`/`front_right` (`front` → `front_left`).

## Review Focus

- A scene whose bodies only touch (stacked, or side by side face to face): no spurious intersection lines, no gaps.
- A low camera below the top of a tall body (`elevation: low`): stacked bodies hidden correctly, no lines through faces.
- A body completely inside another or behind another: warning, no crash, label warning.
- Degenerate input (zero/negative sizes, unknown `on`, cycles, stacking on a sphere, 41 bodies): clear errors.
- WebGL missing or failing in the editor: the line drawing is inserted and a warning reaches the model.

### Task 2: Line drawing – curves, visibility, intersections, SVG

**Files:**
- Modify: `packages/shared/worksheet-3d.js`
- Test: `packages/shared/test/worksheet-3d.test.js`

**Interfaces:**
- Consumes: Task 1.
- Produces: `Worksheet3d.render(block, { widthMm, maxHeightMm, font, color }) -> { svg, widthMm, heightMm,
  warnings: string[], render: { style, widthMm, heightMm, view: number[16], proj: number[16], light: [x,y,z],
  bodies: [{ shape, dims, matrix: number[16], color, faces? }], ground: { corners, color } | null } }`.

- [ ] **Step 1: Write failing tests** – (a) two cubes one behind the other: the back cube contributes fewer visible
  line pieces than alone and none of its visible points project inside the front cube's projected face interior;
  (b) a lone sphere: one closed visible outline, `hidden_edges: 'dashed'` adds a dashed equator half; (c) a cube on a
  cube (stacked): no intersection curves; (d) a cylinder sunk into a cuboid: intersection curve present; (e) a
  sphere completely inside a cuboid → warning `bodies[1] … not visible`; label on it → label warning;
  (f) `elevation: 'low'` with a tower: deterministic SVG, no NaN; (g) oblique projection: front face of a cube is a
  square in the SVG (equal width/height within 0.1 mm); (h) 40-body scene renders in < 1500 ms; (i) visible line
  endpoints of a cube meet (closed outline: every endpoint coincides with another within 0.05 mm).
- [ ] **Step 2: Run** `pnpm test:shared` – FAIL.
- [ ] **Step 3: Implement** candidate curves (feature edges with own-body visibility = at least one adjacent face
  front-facing; analytic silhouettes of sphere/cylinder/cone; rim circles; equator in dashed mode; ground plate
  edges), intersection curves (marching squares of the other body's inside function on each surface patch; skip
  stacked pairs; tolerance so touching faces give no curve), visibility (sample every ≤ 0.25 mm on paper, bisect
  transitions; a point is hidden if a ray towards the viewer passes through another body by more than ε, or the
  own-body test fails), framing (projected extent + margin → mm), SVG (round caps/joins; outline 0.6 mm, colored
  0.45 mm, dashed 0.3 mm), labels (circled, white fill, at the visible sample nearest to the centroid of the body's
  visible samples), warnings.
- [ ] **Step 4: Run** `pnpm test:shared` – PASS.
- [ ] **Step 5: Commit** `worksheet-3d: hidden-line drawing, intersections, labels`.
